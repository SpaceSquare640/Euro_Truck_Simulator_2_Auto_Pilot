# Python UI status and control services

This service reads the existing `Local\ETS2AP_Telemetry_v1` mapping and publishes informational `ui.v1` status snapshots on `\\.\pipe\ETS2AP_UI_v1`. It uses only the Python standard library. UI IPC v1.2 adds a diagnostic Control.v1 connection/state summary while preserving v1.1 and v1.0 negotiation. When the WPF app has a valid saved game folder, it also verifies the native Control.v1 server against that folder's canonical `bin\win_x64\eurotrucks2.exe` path and reads native status. The service and the `DriverAssistRuntime` remain observation-only: the runtime's command candidate is never forwarded, and the Control.v1 client sends only neutral/disengaged packets. A well-formed `engage` request returns `CONTROL_UNAVAILABLE`; malformed requests return `MALFORMED_MESSAGE`. The UI Engage button remains disabled.

For a packaged install, the WPF app starts `runtime\python.exe -I -S -m ets2ap.ui_server` with its own executable path as the trusted UI image and, when available, the selected ETS2 executable as the trusted Control.v1 server image. The MSI places the Python modules under `python\ets2ap` and adds `..\python` to the embedded runtime's isolated module search path. The peers compare canonical process image paths and current-user SIDs before exchanging messages. Changing the saved game folder restarts the Python service so the trusted path stays current. The app allows one automatic restart after an unexpected service exit and terminates the child process when the app closes. If the runtime or service module is missing, the UI remains offline.

For a development pipe smoke check, run the service with `--trusted-ui-image <absolute path to ETS2AP.Ui.Checks.exe>`, then run `ETS2AP.Ui.Checks.exe --ipc-smoke <absolute path to the same python.exe>`. The application does not accept an external Python path for its packaged service.

The server creates a single-client, byte-stream Windows named pipe with a current-user DACL, remote-client rejection, first-instance ownership, and overlapped I/O. It accepts `hello`, `get_status`, and `disengage`; `set_config` and actual engagement are not implemented. Missing, invalid, or stale telemetry never makes the service ready. If the trusted ETS2 image is unavailable, the service does not connect to the Control.v1 pipe.

The WPF app publishes `perception.v1` frames and input/focus observations through a read-only shared mapping. `ets2ap.perception.PerceptionReader` validates the seqlock, layout, sequence, timestamp, and frame age; `ets2ap.driver_runtime.DriverAssistRuntime` combines these frames with telemetry and a bounded lane-centering/speed policy. UI IPC v1.2 reports perception and native Control.v1 connection/state diagnostics to the Overview; v1.1 peers continue to receive perception without the control summary. The RGB lane estimator and front-clear heuristic are prototypes, not validated highway perception. The runtime defaults `front_detector_validated` to false, so commands remain neutral.

The `ets2ap.control_client` module implements the Control.v1 binary codec and a Windows named-pipe client. Its overlapped handle uses security identification QoS; before sending, it checks the server's canonical executable path and current-user SID, then sends a neutral sequence-1 handshake. Status packets are validated and must complete within 100 ms. The service permanently sets the client authorizer to false and sends only neutral/disengaged packets. Its neutral heartbeat runs every 50 ms on a separate thread so status updates cannot trigger additional commands. The runtime defaults `front_detector_validated` to false, the WPF input-monitor health flag remains false, and the UI never authorizes engagement. Therefore no non-neutral driver candidate can reach the native input device and automatic driving remains unavailable.

The native Control.v1 server trusts the bundled Python runtime path registered under `HKLM\SOFTWARE\Kingsley\ETS2 Auto Pilot\InstallLocation\runtime\python.exe`. The WPF app launches the Python service; it optionally starts the Control.v1 status/neutral client when the trusted ETS2 executable path is available. Automatic driving remains unavailable.

Offline checks: set `PYTHONPATH=python` and run `python -m unittest discover -s python/tests -v`. Native cross-process Control.v1 interoperability is exercised by `native/plugin/tests/control_host_tests.cpp` with `ETS2AP_TEST_PYTHON` set to the bundled runtime path. These checks do not prove game telemetry, display capture compatibility, physical-controller coverage, detector accuracy, installer behavior, or in-game control.

GitHub Actions detects this module by its `ets2ap/` and `tests/` directories, compiles the package, and runs the standard-library `unittest` suite. The current Python module has no third-party package dependencies.
